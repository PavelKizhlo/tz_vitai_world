# CLAUDE.md

## Описание проекта
Лендинг для небольшой обжарки с работающей формой заявки. Это маленькая мастерская: обжаривают партиями по 5 кг с 2019 года. Основатели — Аня и Дмитрий, раньше работали бариста. Обжаривают по четвергам, по пятницам развозят по Минску. Свежесть — главное, что они продают: зерно приходит к клиенту на 1–3 день после обжарки.

## Правила именования коммитов

- Коммиты пишутся на русском языке.
- Длинна текста не более двух предложений, желательно одно.
- Префикс для обозначения типа сделанных работ ("feat:", "fix:", "doc:", "chore:", "ref:")
- Общее описание сделанных работ, без подробностей. Например: "fix: исправлено переполнение на мобильных устройствах" или "feat: добалена форма обратной связи"

## Git-workflow

- Основная ветка разработки — `develop`, не `main`. Работа ведётся напрямую в ней: коммиты линейные, пушатся в `origin/develop` по ходу дела, без PR на каждое изменение — автор проверяет их сам через `git log`/`git diff`/просмотр коммитов на GitHub.
- В `main` изменения попадают только через Pull Request из `develop`, когда там накопилась партия готовых изменений (а не после каждой мелкой правки). Мерж PR производится вручную.
- `main` и `develop` не форсить и не переписывать историю; расхождения между ними разрешаются обычным мерджем.

## Правила проверок кода

- После внесения небольших и понятных изменений (например, верстки и стилей) не запускать билд и компиляцию TypeScript.
- После завершения крупных и средних фич, запускать и билд и компиляцию.
- Не запускать дев-сервер и браузерное расширение без прямой инструкции.
- Визуальная проверка вёрстки — только через **playwright CLI** (скилл `playwright-cli`), браузерное расширение для этого не использовать. Перед запуском обязательно спросить согласие пользователя и дождаться его — сам по себе прогон не начинать.
